## File names and the URLs they make

Every row was generated by `@tanstack/router-plugin` 1.169 from the scaffold's `src/routes`.

| File | Route id | URL |
|---|---|---|
| `__root.tsx` | `__root__` | wraps everything |
| `index.tsx` | `/` | `/` |
| `users/index.tsx` | `/users/` | `/users` |
| `users/new.tsx` | `/users/new` | `/users/new` |
| `users/$userId.tsx` | `/users/$userId` | `/users/<id>`, `params.userId` |
| `users/$userId/activity.tsx` | `/users/$userId/activity` | `/users/<id>/activity`, rendered inside `$userId.tsx`'s `<Outlet />`; without one, the URL shows the detail page |
| `users/$userId_/edit.tsx` | `/users/$userId_/edit` | `/users/<id>/edit`, a child of the root, not of `$userId.tsx` |
| `users/route.tsx` | `/users` | layout for every `users/*` file; renders `<Outlet />` |
| `_signed-in.tsx` + `_signed-in/reports.tsx` | `/_signed-in/reports` | `/reports` |
| `(admin)/reports/index.tsx` | `/(admin)/reports/` | `/reports`; the group only folds files together |
| `-fixtures/data.ts` | none | ignored: the `-` prefix (`routeFileIgnorePrefix`) |
| `users/index.test.tsx` | none | ignored by the scaffold's `routeFileIgnorePattern` |

- `createFileRoute` takes the route id, not the URL: `createFileRoute("/users/")` for `users/index.tsx`. The generator rewrites a wrong id when it runs, and fills an empty new file with a stub route (single quotes, no semicolons; `pnpm format` fixes it).
- A pathless layout file (`_name.tsx`) without a `component` renders its children through an implicit `<Outlet />`. Give it a `component` only for a shell (header, sidebar) and call `<Outlet />` in it.
- A `(group).tsx` file is an error: "A route configuration for a route group was found ... Did you mean to use a layout/pathless route instead?"
- Do not create `-components/` folders under `routes/`: UI goes to the feature folder, which `frontend-project-structure` owns.

## The generated route tree

- `src/routeTree.gen.ts` is written by the plugin whenever Vite starts: `pnpm dev`, `pnpm build` and Vitest all regenerate it. Commit it, so `tsc` and Biome work on a fresh clone without a Vite run.
- Biome excludes it in `biome.json` (`"!src/routeTree.gen.ts"`), and knip never sees it as dead code because `src/app/router.tsx` imports it.
- It also declares `FileRoutesByPath`, which types every `createFileRoute(...)` string; a type error naming `FileRoutesByPath` after adding a file means the tree has not been regenerated yet.

## What `autoCodeSplitting` splits

The scaffold turns it on for `vite` and `vite build` (`autoCodeSplitting: !process.env.VITEST`). The default groupings put `component`, `errorComponent` and `notFoundComponent` each in their own lazily loaded chunk. `pendingComponent`, `validateSearch`, `loaderDeps`, `beforeLoad` and `loader` stay in the entry chunk, so zod, the query option getters and every pending component count against the entry budget: keep a pending component to plain markup. `__root.tsx` is never split.

A module-level value that both the loader and the component use (a schema, a constant) is moved into a shared module by the plugin; that is fine.

## What defeats it

Measured on the scaffold with `pnpm build` (entry plus its static imports, gzip; budget 160 KB, scaffold about 148 KB):

| Change | Entry | Router output |
|---|---|---|
| `export function NewUserPage` in `users/new.tsx` | about 19 KB more, build fails the budget | nothing: the component was the route's only split part |
| `export function ComparePage` in a route that also has a `notFoundComponent` | grows by the page and its imports | `[tanstack-router] These exports from ".../compare.tsx" will not be code-split and will increase your bundle size: - ComparePage` |
| `users/index.tsx` loader and component import from one barrel (`@/features/users/index.ts` re-exporting `toListParams` and `UserTable`) | about 1 KB more: `UserTable` and its imports move into the entry chunk | nothing |

So a route file exports only `Route`, features have no `index.ts` barrels, and the loader's imports (query options from `@/api/generated/api`) come from a different module than the component's (`@/features/users/user-table`).

## Reading route state outside the route file

A feature component gets params and search as props from the page component. The one exception is a component used by exactly one route, when the value would otherwise pass through several layers: it reads the route's typed API by id. A feature never imports `Route` from a route file. A link or navigation that updates the current route's search names that route's full path as a literal in `from`, which the generated tree types like `Route.fullPath`.

```tsx,verify
import { getRouteApi, Link } from "@tanstack/react-router";

const userRoute = getRouteApi("/users/$userId");

export function UserBreadcrumb() {
  const { userId } = userRoute.useParams();
  return <span>{userId}</span>;
}

export function NextPageLink({ page }: { page: number }) {
  return (
    <Link from="/users/" search={(prev) => ({ ...prev, page: page + 1 })}>
      Next
    </Link>
  );
}
```
