## `Dockerfile`

```dockerfile
# syntax=docker/dockerfile:1

FROM node:26.13.1-trixie-slim@sha256:e6bedef217677b276c591795e169840edd9096dbf13f29df8ef8d1856b8820bc AS build
# Node 25+ ships no corepack: install the pnpm that package.json's devEngines pins.
RUN npm install --global pnpm@12.21.0
WORKDIR /app
# Lockfile only: this layer survives every source edit.
COPY pnpm-lock.yaml pnpm-workspace.yaml ./
RUN --mount=type=cache,id=pnpm-store,target=/pnpm/store \
    pnpm fetch --store-dir /pnpm/store
COPY . .
RUN --mount=type=cache,id=pnpm-store,target=/pnpm/store \
    pnpm install --offline --frozen-lockfile --store-dir /pnpm/store
# One image per environment: the origins are baked into the bundle and the CSP.
ARG PUBLIC_API_ORIGIN
RUN pnpm build \
    && mv dist/headers.caddy /headers.caddy \
    && rm dist/_headers dist/.assetsignore \
    && find dist -name '*.map' -delete

FROM caddy:2.11.9-alpine@sha256:003a97808e781aa9f7e75cc2f43d34d461099031faf5e20faefb9f61126836f0 AS caddy

FROM scratch
COPY --from=caddy /usr/bin/caddy /caddy
# Go's built-in MIME table lacks woff2 and webmanifest.
COPY --from=caddy /etc/mime.types /etc/mime.types
COPY deploy/Caddyfile /etc/caddy/Caddyfile
COPY --from=build /headers.caddy /etc/caddy/headers.caddy
COPY --from=build /app/dist /public
# Numeric: Kubernetes runAsNonRoot cannot verify a named user, and scratch has no passwd.
USER 65532:65532
EXPOSE 8080
ENTRYPOINT ["/caddy", "run", "--config", "/etc/caddy/Caddyfile", "--adapter", "caddyfile"]
```

Every `PUBLIC_*` name in `PUBLIC_ENV` needs its own `ARG` line before `RUN pnpm build`; a missing
one fails the image build with `Error: PUBLIC_<NAME> is not set`. `.dockerignore` excludes `.env*`,
so `.env.development` never reaches the image. The maps are deleted after the build; upload them
from the CI build first if an error tracker needs them.

## `deploy/Caddyfile`

```caddyfile
{
	admin off
	persist_config off
	auto_https off
	# TLS ends upstream and the root filesystem is read-only: no certificate storage to tidy.
	storage_check off
	storage_clean_interval off
	grace_period 10s
	log {
		format json
	}
}

# Generated by `pnpm build` from deploy/headers.ts.
import /etc/caddy/headers.caddy

:8080 {
	root * /public
	log
	encode zstd gzip
	header {
		import all_headers
	}

	handle /healthz {
		respond "OK" 200
	}

	# A missing hashed file is a 404, never index.html, and only a found file is cached for a year.
	handle /assets/* {
		file_server
		header {
			match status 200 304
			import assets_headers
		}
	}

	handle {
		try_files {path} /index.html
		file_server
	}
}
```

- The global options are what a read-only root filesystem needs: without `admin off`,
  `persist_config off` and the two storage options, Caddy tries to write lock and config files.
- `all_headers` and `assets_headers` are the snippets `caddyHeaders()` generates; never write
  headers into the Caddyfile by hand.
- `handle /assets/*` has no `try_files`, so a missing chunk is a 404 with `no-cache`, and
  `match status 200 304` keeps `immutable` off that 404.
- `grace_period 10s`: on SIGTERM Caddy logs "grace period initiated", finishes open requests, and
  exits 0.

## Why Caddy on `scratch`

The runtime image holds one static binary, its MIME table, the Caddyfile, the generated header
snippets and `dist/`: no shell, no package manager, about 65 MB. A missing hashed asset is a real
404, `/.well-known/` is served, HEAD works on SPA routes, and the access log is JSON with the
status. No shell also means no entrypoint script: configuration cannot be injected at start, which
is why the image is built per environment.

## Run flags and the Kubernetes security context

```bash
docker build --build-arg PUBLIC_API_ORIGIN=https://api.example.com -t app .
docker run --read-only --cap-drop ALL --security-opt no-new-privileges -p 8080:8080 app
```

The same constraints in a pod spec:

```yaml
securityContext:
  runAsNonRoot: true
  runAsUser: 65532
  runAsGroup: 65532
  readOnlyRootFilesystem: true
  allowPrivilegeEscalation: false
  capabilities:
    drop: [ALL]
  seccompProfile:
    type: RuntimeDefault
readinessProbe:
  httpGet:
    path: /healthz
    port: 8080
livenessProbe:
  httpGet:
    path: /healthz
    port: 8080
```

Port 8080 needs no `NET_BIND_SERVICE`. Probes and hooks are `httpGet`: the image has no shell for
an `exec` probe. TLS ends at the ingress; the HSTS header Caddy sends takes effect once the
browser receives it over HTTPS.

## The curl checklist that proves a deployment

Run against the deployed URL (or `http://127.0.0.1:8080` for a local container). Take a real chunk
name from `curl -s "$URL/" | grep -o '/assets/index-[^"]*\.js'`.

| Request | Expected |
|---|---|
| `curl -sI "$URL/"` | 200, `Cache-Control: no-cache`, the full CSP with every `PUBLIC_*` origin in `connect-src`, HSTS, `nosniff`, `Referrer-Policy`, `Permissions-Policy`, COOP, CORP |
| `curl -sI "$URL/users/123"` (a deep link) | 200 `text/html`, `no-cache` |
| `curl -sI "$URL/assets/index-<hash>.js"` | 200 `text/javascript`, `public, max-age=31536000, immutable` |
| `curl -sI "$URL/assets/index-MISSING.js"` | container: 404 with `no-cache`; Cloudflare: 200 `text/html` with `immutable` (the known limit) |
| `curl -s -o /dev/null -w '%{http_code}' "$URL/assets/index-<hash>.js.map"` | container: 404; Cloudflare: the SPA's HTML, never a map |
| `curl -sI -H 'Accept-Encoding: zstd, gzip' "$URL/assets/index-<hash>.js"` | `Content-Encoding: zstd`, `Vary: Accept-Encoding` |
| `curl -s "$URL/healthz"` | `OK` (container only) |
| `docker inspect <container> --format '{{.Config.User}} {{.HostConfig.ReadonlyRootfs}}'` | `65532:65532 true` |

A single wrong line (a map that answers 200, `immutable` on HTML, a CSP without the API origin)
blocks the release.

## Compression

`encode zstd gzip` compresses each response on the fly, picking from `Accept-Encoding`. Cloudflare
compresses on its own; nothing is precompressed in the build. Precompressed `.br` and `.gz` files
served by `file_server { precompressed br gzip }` save CPU per request and are an optional later
step: they need a build script that writes them and a `precompressed` line in both `file_server`
blocks.

## Changing the image

- A new `PUBLIC_*` name: one more `ARG` line, and the deploy pipeline passes `--build-arg` for it.
- A new file in `public/` (`robots.txt`, `.well-known/security.txt`): nothing to change; it is
  served with `no-cache`.
- New Caddy or Node versions: update the tag and the digest together.
